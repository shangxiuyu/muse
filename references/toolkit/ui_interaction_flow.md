# UI 视线重力与心流哲学 (Visual Gravity & Interaction Flow)

本文件是 Muse UI 系统的**灵魂与心流法则**。它融合了专业前端工程设计的文本即设计哲学与香奈儿克制法则。高级界面的最高境界是**“透明性（Invisibility）”**——用户沉浸在自己的创造与思考中，感受不到界面的阻碍。

## 1. 视线重力与动线法则 (Visual Gravity & Scanning Flow)

用户的注意力是有限的物理流体，界面设计必须建立清晰的引力场。

### 1.1 第 1 秒单一锚点法则 (The 1-Second Anchor)
* **全局唯一主引力源**：视口在初次加载的第 1 秒内，**只能有且仅有 1 个最强视觉焦点**（如编辑器中心光标、核心搜索条或大标题）；
* **禁止注意力内战**：严禁在页面不同区域同时使用高饱和度徽章、跳动按钮或高对比度闪烁，避免视线在多个焦点间来回撕扯。

### 1.2 视线滑梯与动线闭环 (The Eye-Scanning Slide)
* **自然阅读滑梯**：遵循 F 型（密集信息）或 Z 型（展示型）动线。左上角确立上下文 $\to$ 中间承载核心操作 $\to$ 右下角/底部承接最终动作；
* **动作后的视线归宿 (Visual Rest)**：用户触发任何操作后（如点击“保存”或“生成”），界面反馈必须精准出现在**原操作点附近或预期的结果落脚点**，严禁让视线在屏幕两端无序大幅跳跃。

## 2. 香奈儿克制与 80% 静默退让法则 (Chanel's Mirror Restraint)

真正高级的美感来自于**在不该打扰时保持极致的沉默**。

### 2.1 香奈儿镜子法则 (Chanel's Mirror Principle)
* **“出门前照一下镜子，摘掉一件配饰”**：
  * 在完成设计后，必须进行一次主动精简：审视页面上是否存在为了“显得高级”而强行添加的无意义装饰（多余的发光边框、装饰性小晶体、无关联的标签）；
  * **把最大的锋芒留给 1 个核心元素**，其余所有元素必须保持安静与克制。

### 2.2 80% 静默公理 (The 80% Silence Rule)
* **80% 的日常浏览、阅读与打字必须是完全静止与无声的**；
* 动效与触感微音律（Tactile Audio）只能分配给那 **5% 的关键状态跃迁**（如：灵感关联涌现、任务彻底完成）；
* 严禁在常驻图标或卡片边框上施加无休止的旋转或呼吸动画。

## 3. 文本即设计哲学 (Writing in Design)

文字是界面最核心的设计材料，不是事后的组件填空。

### 3.1 用户视角的直白表达 (User-Centric Vocabulary)
* **使用用户理解的日常语言**：命名必须从用户意图出发，严禁暴露系统内部工程逻辑（例如：写“管理通知”，绝不能写“配置 Webhook”；写“导出数据”，绝不能写“执行 Payload 序列化”）；
* **动词全链路闭环 (Action Vocabulary Cohesion)**：全流程使用相同的词汇链条——点击按钮“发布手记”，弹出的反馈必须严格写“手记已发布”，建立明确的心理路标。

### 3.2 空状态即行动邀请 (Empty State as Invitation)
* 空状态绝不是一句冰冷的“暂无数据”；
* 它必须由三部分组成：
  1. **意境启发**：一句引人深思的提示（如：“空白画布，等待第一缕火花…”）；
  2. **明确行动起点**：一个聚焦的初始动作按钮（如：“创建第一篇手记”）；
  3. **范例预览**：可一键载入的优质模板。

### 3.3 错误状态作为自愈指引 (Errors as Direction)
* **严禁道歉与冰冷报错**：不写“对不起，发生未知错误 500”；
* **直接提供修复路径**：使用温和的琥珀色调，明确说明发生了什么以及如何一步解决（例如：“网络连接稍显迟疑，已为你自动保存草稿 · [点击重试]”）。

## 4. 认知摩擦消除与渐进披露 (Progressive Disclosure)

* **复杂功能藏于二阶**：首屏只展示最高频的 20% 核心功能；
* **次要与高级设置**：通过悬浮触发、折叠面板或 Command Palette 快捷调出，保持视口长期的清爽与低负荷。
