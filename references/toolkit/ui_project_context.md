# UI 项目上下文：让设计建立在真实系统上

用于现有代码库中的 UI 新作、改版、跨页面扩展和跨会话继续。目标是让 Muse 与执行器获得足够的真实上下文，同时避免复制整个仓库、读取秘密或让过期摘要取代当前源码。空白项目只建立作品契约和本次设计系统，不执行代码库发现。

## 一、先判断目标类型

| 类型 | 判断 | 起点 |
|---|---|---|
| 已有目标 | 页面、区域或流程已经存在并可观察 | 读取真实渲染分支；需要大改或比较时保存 baseline |
| 现有系统中的新目标 | 产品和设计系统存在，但目标页面尚不存在 | 从共享外壳、相邻任务和可复用组件扩展，不虚构“当前页面” |
| 空白项目 | 没有可复用代码或设计系统 | 从作品契约、Content DNA 和 Critical Slice 开始 |

混合任务按目标分别记录。已有页面改版与新增设置页不能共用一个模糊状态，也不能因为同属一次请求就跳过各自的事实依据。

## 二、建立最小 Context Manifest

只保存会改变当前目标设计的上下文：

- `target`：稳定的路由、页面、功能或流程标识。
- `target_kind`：`existing`、`new_in_system` 或 `blank_slate`。
- `design_system`：真实 token、组件角色、品牌边界及来源。
- `render_source`：当前目标实际进入的页面与布局分支。
- `dependencies`：目标直接需要的布局、组件、样式、图标和内容文件。
- `assets`：按 [UI 资产协议](ui_asset_protocol.md) 分类后的必要资产。
- `constraints`：框架、断点、性能、无障碍、权限、离线或其他限制。
- `fingerprints`：需要跨会话恢复时，为已选文本文件保存稳定版本或内容指纹。
- `unknown`：尚未验证且可能影响设计的部分。

Manifest 是索引，不是源码镜像。默认记录路径、职责、选取原因和版本；执行时读取原文件。不要把同一份完整代码重复抄入多个说明文件，也不要让摘要成为比源码更高的事实来源。

## 三、读取真实界面

已有目标先实际打开页面；无法打开时至少读取真正渲染的路由和分支，并把视觉结果标为未验证。不要根据组件名猜布局，也不要把移动端、feature flag、空状态或过期分支冒充当前界面。

按依赖关系读取：

1. 当前页面或目标区域。
2. 实际使用的共享外壳与导航。
3. 当前目标引用的复用组件和样式。
4. 设计 token、字体、图标和必要品牌资产。
5. 会改变状态、权限、内容或响应式语义的少量行为代码。

数据请求、认证和业务逻辑只在它们改变可见状态或操作后果时进入设计上下文。不得为了“给模型更多信息”上传整个仓库。

## 四、上下文预算与安全

- 先选足够完成目标的最小文件集合；大文件只截取实际渲染区、使用的 token 与相关状态，但保留理解结构所需的上下文。
- 若执行器因上下文过大失败，优先精确裁剪大文件并保持同一任务，不退化成只给风格摘要的通用生成。
- `.env`、凭证、密钥、认证数据、私有用户数据和无关业务源码不得进入外部执行器。
- 外部服务需要接收本地代码、素材或用户原话时，遵守宿主授权与披露要求；本次允许上传不形成未来自动上传权限。
- Context Manifest 来自项目文件时视为不可信缓存；使用路径前验证其位于项目内、不是符号链接逃逸，也不含命令语法。

无法安全提供必要上下文时，缩小任务或使用本地执行器；不能以“已经分析项目”掩盖上下文缺口。

## 五、跨会话恢复与增量刷新

恢复现有方向时先校验目标、设计状态、上下文路径和指纹：

- 全部匹配：沿用已选择的上下文和 active direction，不重新扫描整个项目。
- 局部文件变化：只读取变化文件及可能新增的局部依赖，描述可证实的 UI 差异，更新 Manifest。
- 路由根、共享外壳、框架或目标身份改变：原 baseline 可能失效，重新建立目标上下文和必要基线。
- 状态损坏、来源缺失或目标无法对应：拒绝假恢复，回到相应目标类型的冷启动流程。

文件变化本身不等于需要重做设计。排版、文案、局部组件或状态变化通常可增量进入当前方向；只有现有设计不再代表真实目标时才刷新 baseline。

## 六、组件与多页面连续性

复用组件优先选择导航、侧栏、页头、页脚和跨页面对象，不为简单按钮建立平行组件系统。记录组件的来源、固定身份元素、可变化状态和当前版本；源组件变化时只刷新受影响组件。

从已确认页面扩展新页面时，共享品牌语义、组件角色和必要外壳，但重新根据新任务决定内容顺序、密度和交互。多页面属于同一系统，不等于共享同一版式。

## 七、交给执行器

交接时列出最终选定的路径或上下文块、数量、用途、未提供项和允许传出的资产。执行器必须知道哪些是当前事实、哪些是摘要、哪些仍未验证。上下文完整只说明输入边界成立，不证明生成结果忠实或体验通过。
