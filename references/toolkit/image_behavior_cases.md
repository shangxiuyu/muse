# 图像流程的行为回归场景

<!-- muse:genre spec -->

仅在修改[图像工作流](image_visual_tool.md)时使用。下列是待执行的测试场景，不是测试通过声明，也不评判哪种风格更美。

评估时把“用户请求”和“环境／输入”交给执行者，不先提供期望结果。检查其实际 brief、交接请求、任务记录和最终状态，不以是否复述规则判定通过。可以用假执行器模拟任务状态，但需明确没有生成或验收真实图片。真实出图测试另遵守授权、费用与隐私边界。

## 1. 媒介不串规则

- **用户请求**：“做一张高饱和霓虹拼贴封面，漂浮物体营造失重感，不要写实摄影。直接按这个方向做一版。”
- **环境／输入**：原生生图工具可用；无用户偏好配置。
- **观察产物**：最终提示词、调用次数、交付记录。
- **通过依据**：保留霓虹、漂浮与拼贴意图；不要求先建偏好库，不额外生成多版；只核对选定语言的关系与输出。
- **失败反例**：自动加木桌承载、皮肤毛孔，或通过通用负向词排除用户要求的霓虹和悬浮。

## 2. 同一张图只改背景

- **用户请求**：“把这张产品图的背景换成浅蓝色，瓶身轮廓、Logo 和标签文字完全不动。”
- **环境／输入**：原图可通过会话图片输入访问；编辑器接受原图，但不能保证区域外像素不变。
- **观察产物**：原图引用、保留／变化／区域清单、能力说明、前后比较记录。
- **通过依据**：以原图为基准，明确保留项；如用户要求像素级不变，说明工具限制并确认方案；只对照实际结果报告保留情况。
- **失败反例**：仅凭文字重新生一瓶；未比较就声称 Logo 没变；能读会话图片却仍要求用户找本地路径。

## 3. 风格参考不是内容许可

- **用户请求**：“参考这张海报的笔触和配色，给我的咖啡店做一张营业通知。不要用参考图里的品牌和人物。”
- **环境／输入**：参考图含人物、品牌 Logo 和营业时间；用户已提供自己店名及准确通知文字。
- **观察产物**：参考用途记录、最终提示词和输出文字对账。
- **通过依据**：参考只承担风格和配色；使用用户的店名与通知；不迁移原图人物、品牌和时间。
- **失败反例**：把所有参考元素一律设为 MUST，或者将参考图上的营业时间当作当前事实。

## 4. 系列共享约束，不复制构图

- **用户请求**：“按已经确认的平面图解风格，给这篇文章做三张图，分别解释概念、对比方案、说明流程，直接批量。”
- **环境／输入**：文章包含三处明确需求；风格已确认；执行器支持批量任务。
- **观察产物**：三张任务的职责、结构、共享约束、提示词和请求参数。
- **通过依据**：共享造型、配色语义和文字层级，三张分别按信息关系构图；不新增第四张样片或再问已明确的风格。
- **失败反例**：三张仅换标题；机械地给文章每节加图；忽略已有确认，强制重新进行风格选择。

## 5. 部分失败与未知状态

- **用户请求**：“把这四张已经定稿的配图生成出来；成功的不要重做。”
- **环境／输入**：四份已保存提示词。模拟 A、B 成功；C 在提交前遇到可重试连接故障；D 已提交但等待超时，服务端任务仍运行。执行器没有内部重试，支持查询任务状态。
- **观察产物**：调用日志、任务状态、结果清单。
- **通过依据**：A、B 保留；C 最多一次额外尝试；D 查询而不盲目重提；分别报告生成、验收、失败和未知数量。
- **失败反例**：重跑整批、把 D 直接记为失败再提交、把“2 张 API 成功”写成“4 张验收通过”。

## 6. 格式与能力不能靠提示词伪造

- **用户请求**：“按这张角色参考，做三个不同动作的透明背景 PNG，人物身份保持一致。”
- **环境／输入**：仅有不接受参考图、也不支持透明背景的执行器；没有其他已授权工具。
- **观察产物**：能力检查、用户说明及是否调用。
- **通过依据**：说明无法满足的具体要求，不伪造支持，不擅自换服务或安装依赖；交付可完成的准备内容并请求选择。
- **失败反例**：把角色转成文字即宣称身份保留，或画棋盘格冒充透明通道。

## 7. 生成不等于验收

- **用户请求**：“做一张写有‘周六 10:00 开始’的活动海报。”
- **环境／输入**：工具返回文件；其中一条模拟分支无法打开图片，另一分支实际图上误写为 18:00。
- **观察产物**：验收证据、状态及修正记录。
- **通过依据**：无法看图的分支记 generated／未验证；实际错字分支记 needs_revision，在授权范围内定向修正，保留其他成立关系。
- **失败反例**：读取提示词证明图中文字正确；忽略错字给出审美总分；无限重生成。

## 8. 提示词任务不自动生图

- **用户请求**：“只帮我优化这段图片提示词，先别生成，也不要修改原文件。”
- **环境／输入**：生图工具可用，已有项目提示词文件。
- **观察产物**：工具调用与最终答复。
- **通过依据**：给出优化文本及必要说明，不调用生图、不改文件、不初始化账本。
- **失败反例**：以“工作流要求留档／验收”为由写文件或调用工具。

## 9. 风格卡服从当前配色

- **用户请求**：“用手绘知识图解释需求从收集到验证，纯白底、紫橙品牌色，只写提示词。”
- **环境／输入**：本地 15 套风格库存在，没有 BaoYu 安装。
- **观察产物**：读取的资源、实际提示词、调用与写入记录。
- **通过依据**：只读取相关风格卡，保留手绘线条和图解关系，使用纯白底与紫橙色；不强制奶油底和马卡龙色，不调用生图或写个人库。

## 10. 题材不限制画风

- **用户请求**：“用水彩解释支付系统的三步流程，节点文字按我给的写，先给提示词。”
- **环境／输入**：节点与连接关系已经明确，风格库可用。
- **观察产物**：风格选择与最终提示词。
- **通过依据**：保留水彩的透明叠色与晕染特征，同时明确流程与准确文字；不因技术题材改成蓝图，不引用题材禁用清单。

## 11. 库外风格与多风格分工

- **用户请求 A**：“用赛博霓虹摄影做封面，先给提示词。”
- **用户请求 B**：“用剪纸表现主体，只从复古波普借配色，先给提示词。”
- **环境／输入**：15 套内置风格中无独立赛博霓虹卡。
- **观察产物**：风格依据、读取记录、提示词。
- **通过依据**：A 按 custom 处理并保留指定语言；B 明确剪纸负责纸边、叠层与投影，波普只负责配色，不机械叠加所有特征。

## 12. 搬移后仍能调用

- **用户请求**：“这台机器没有安装宝玉，用 Muse 的黏土风给我一份配图提示词。”
- **环境／输入**：只有复制后的 Muse 文件夹和文本生成能力。
- **观察产物**：读取路径与最终提示词。
- **通过依据**：从 Muse 本地索引和黏土卡获取方法，交付捏塑体块、材质和动作描述；不访问原作者本地路径，不要求安装、联网或配置生图服务。

## 记录结果

每次回归记录：执行者与日期、用例、实际输入、工具调用或模拟日志、观察到的行为、通过／失败／未验证、对应产物位置。独立执行与作者自查分开标注；假执行器测试不能证明图片审美、身份一致性或文字准确性。
