# UI 迭代协议：直接修改、精修与分支探索

用于持续设计同一页面、功能或流程。它把方向选择、版本历史和真实验收分开，避免一句局部反馈触发整页重做，也避免用户已经选定方向后继续无意义发散。协议不绑定特定画布、模型、文件格式或生成服务。

## 一、设计状态

需要跨轮或跨会话继续的目标，可保存以下最小状态：

- `baseline`：已有目标在修改前的真实状态；新目标可为 `none`。
- `active_direction`：当前被用户选择或任务明确指向的方向。
- `branches`：用户要求比较的替代方向；不自动选择赢家。
- `versions`：同一方向上的可恢复修订。
- `context_manifest`：本次使用的项目上下文及版本，见 [UI 项目上下文](ui_project_context.md)。
- `design_evidence`：Content DNA、结构假设、辨识关系、克制规则和关键取舍。
- `acceptance_evidence`：每个版本实际观察的尺寸、路径、状态、问题和未验证范围。

baseline 不是每个任务的强制仪式。局部修改只需保留受影响区域的修改前事实；已有目标的大改、需要前后比较或来源容易混淆时，才保存可复看的完整基线。

## 二、先选择修改方式

| 模式 | 何时使用 | 约束 |
|---|---|---|
| `direct_edit` | 结果可由用户要求和当前成品精确确定 | 最小修改；不重新解释整体方向 |
| `replace` | 用户继续当前方向，但构图、层级、密度、图文或响应式需要审美判断 | 保持同一方向与版本历史；保留未提及的成立部分 |
| `branch` | 用户明确要求选项、替代方向、实验或比较 | 每个分支必须有实质结构取舍；不静默选中 |
| `revert` | 用户要恢复某个已知版本，或新版本产生明确退化 | 恢复可追溯版本，不把重新生成冒充回退 |

请求大小不决定模式。“把按钮改成 40px”即使涉及多处也是 direct edit；“让首屏更聚焦”即使只改一块，也可能需要 replace。用户已选择某个方向后，后续反馈默认在该方向精修；只有明确要看另一个可能时才 branch。

一个请求同时包含确定性纠错与创意重构时，若重构会覆盖直接修改，把精确约束合并进一次 replace；若两者互不影响，可先完成 direct edit 再处理方向问题。

## 三、分支必须值得比较

分支差异应落在信息关系、观看／操作顺序、密度、图文角色、状态组织或品牌表达通道。只换色、字体、圆角或主图不算独立方向，除非这些变化确实改变任务理解并能说明代价。

为每个分支记录：

- 它保留的共同事实与设计系统。
- 与 active direction 不同的结构假设。
- 服务的目标和牺牲的部分。
- 失效条件与需要验证的 Critical Slice。
- 使用的执行器或模型；不同模型不自动代表不同方向。

方向数量由真实取舍和用户意图决定，不设默认数量。生成会消耗额度或调用外部服务时，未经用户要求不额外扩展分支。

## 四、版本与选择

- replace、direct edit 和 revert 都保留同一方向的版本关系。
- branch 从明确的父版本产生，并记录其目的；多分支返回后仍以原方向为 active，直到用户明确选择。
- 用户用“选这个”“继续这个”“我更喜欢 B”等表达选择后，将对应分支设为 active；此后的普通反馈不再继续分叉。
- 不用版本号推断审美方向；同时保存短描述和来源。
- 状态写入采用完整临时文件再替换，避免中断造成记录损坏；不覆盖无关目标。

状态文件是恢复线索，不是新的审美证据，也不能保存秘密、身份令牌或未授权上传许可。

## 五、局部修改与上下文变化

执行前检查本次要求是否需要源码信息：颜色、文案、间距或成品中已明确可见的元素通常可直接处理；涉及隐藏行为、共享组件或页面关系时，按 [UI 项目上下文](ui_project_context.md) 只扩展必要上下文。

源码局部变化时，把可证实的变化带入 active direction，保留未改变部分；不要仅因文件指纹变化就重新发现整个项目或创建新基线。只有真实页面根、共享外壳或目标身份改变，或用户明确要求从当前实现重新开始时，才刷新 baseline。

## 六、修改后复看

每次迭代记录“请求／观察 → 模式 → 修改 → 复看结果 → 新退化 → 未验证”。direct edit 也要检查受影响状态和断点；replace 需要复看结构假设与克制规则；branch 必须在相同内容、尺寸和任务下比较，不能让更完整的内容量替某个方向制造优势。

选定方向不等于成品通过。进入实现或交付前仍按 [成品验收](../acceptance_protocol.md) 清除阻断项；人的选择只证明当前偏好，不自动证明可用性、事实或普遍审美质量。
