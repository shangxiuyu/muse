# UI 视觉判断：把意图落到画面

这些方法用于在“关系”中做出精确的视觉选择。美是关系的艺术：排版是空间与视线的关系，色彩是层次与能量的关系，字体是性格与声音的关系。默认值只是试排起点，真实业务情境优先。

---

## 一、整体排版与空间系统（空间与视线的关系）

### 1. 反默认居中与 DESIGN_VARIANCE 阶梯
打破大模型条件反射式的“大标题居中 + 副标题居中 + 居中双按钮”。居中适合极度庄重、简短的单一仪式页面；依据 `DESIGN_VARIANCE`（1-10）执行空间架构：
- **Level 1~3 (Predictable)**：经典 12 栅格等分对齐，仅用于严格严谨的公文或单一仪式页；
- **Level 4~7 (Offset / 推荐主流)**：
  - **50/50 动态分屏**：左侧论述主张与核心动作，右侧真实交互面板或数据图示；
  - **负边距叠压（Overlapping）**：`margin-top: -2rem` 制造纵向呼吸与层次穿透；
  - **多比例混排**：4:3 比例展示与 16:9 视口图文穿插，左对齐大标题搭配结构化注解。
- **Level 8~10 (Asymmetric / 先锋社论)**：
  - **CSS Grid 分数列宽**：`grid-template-columns: 2fr 1fr 1fr` 或 `7:3` 黄金非对称分割；
  - **巨幅呼吸留白**：如单侧 `padding-left: 15vw ~ 20vw`，制造杂志般的沉浸感；
  - **移动端强制回退**：任何非对称布局在 `< 768px` 视口下必须强制折叠为严格的垂直单列流，配合 `overflow-x: clip` 杜绝横向滚动。

### 2. 封杀横排 3 等分卡片（NO 3-Column Equal Cards）
- 严禁机械式横排 3 张等大卡片（AI 经典套路）。
- **替代方案**：2 列错位 Zig-Zag、大焦点带双附属面板、横向视口展卷（Horizontal Scroll Pan）、或去除外框的裸排数据列表。

### 3. 负字距精密系统（Negative Tracking）
大字号标题如果使用默认字距，在数字屏幕上会显得松散松垮、缺乏工业精密感：
- **Display 大标题（40px ~ 80px）**：字距必须收紧至 `-0.03em ~ -0.05em`（如 `-1.5px ~ -3px`），标题行高紧凑在 `1.05 ~ 1.15`；**严禁使用斜体（No Italic Headers）**；
- **Headline 章节标题（24px ~ 32px）**：字距微收 `-0.01em ~ -0.02em`；
- **Body 正文与标签（14px ~ 16px）**：字距归零（`normal`），严禁正文压缩字距。

### 4. 网格节奏与 CLS 防跳跃
- **CSS Grid over Flex-Math**：宏观页面结构优先使用 CSS Grid，确保跨断点伸缩确定性，拒绝脆弱的百分比手算；
- **4px / 8px 亲疏倍数**：组内元素（图标与字、标题与段落）使用 4px/8px；组间区块使用 24px/32px/48px。留白必须表达亲疏血缘；
- **CLS 防线**：所有异步媒体、卡片容器必须显式声明 `aspect-ratio` 或最小高度预留，严禁加载后内容剧烈跳跃。

## 二、颜色体系（层次与能量的关系）

### 1. 从具体业务客体（Subject Matter）推导 4–6 色调色板
色彩是业务性格在物理世界中的温度隐喻。**严禁凭空拍脑袋使用泛滥的“通用极客黑”或“大厂灰”**。
从产品客体的真实物理与情境中提纯色彩（如：健康代谢提取自植物鼠尾草与黎明微光、知识库提取自手工纸张与温和墨水、金融与工业提取自精密冷钛与冷轧钢）。

在动手编码前，必须显式定义并命名 **4–6 个具体 Hex 色值的调色板**：
- **Canvas Base**：最底层画布基底（承载 60% 面积）；
- **Surface / Card**：一二级面板与容器衬底（承载 30% 面积）；
- **Border / Hairline**：结构边界与单像素细线；
- **Accent Primary**：业务核心主强调色（占 10% 面积，饱和度严格控制在 80% 以内）；
- **Accent Secondary / Semantic**：辅助功能或语义状态色（如涌现灵感橙、完成确认绿）；
- **Text Primary & Muted**：高可读性正文与次级注释阶梯。

### 2. 警惕暗夜偷懒偏置与 Lila Ban
- **模式决策边界（Mode Decision Contract）**：
  - **深色模式（Dark Track）**：仅适用于夜间/暗光环境使用、长时间高专注极客开发工具、媒体影音流、或以发光 Canvas 节点图谱为主体的界面；
  - **浅色模式（Light Track）**：日间环境、高信息密度表格/表单、深度文章阅读（Editorial/Paper）、生活方式陪伴、消费级应用或常规 SaaS 优先采用浅色纸感；
- **严禁纯黑与紫蓝霓虹渐变（The Lila Ban）**：严禁 `#000000` 死黑；严禁“全黑底 + AI 紫蓝大渐变”与粗暴的 `box-shadow` 外发光。

### 3. 双轨制 6:3:1 黄金律与材质标准

#### A. 浅色轨（Light Track · 现代 Bento 2.0 范式）
高品质浅色界面的核心是**纸墨呼吸感与自然漫反射微投影**，严禁使用惨白底色与肮脏的大黑阴影：
- `Canvas (60%)`：精致中性浅底（如 `#f9fafb` / `#F8F9FA` / 暖米白 `#FBFBFA`），绝不用刺眼的高频纯白 `#FFFFFF` 铺满整个屏幕；
- `Surfaces (30%)`：纯白面板 `#FFFFFF`，搭配单像素极微细边框（`1px solid rgba(15, 23, 42, 0.06)` 或 `border-slate-200/50`）；
- `Diffusion Shadow（扩散漫反射微投影）`：
  ```css
  /* 扩散漫反射轻投影：宽域漫射 + 1px 极微轮廓 */
  box-shadow: 0 20px 40px -15px rgba(0, 0, 0, 0.05), 0 1px 2px 0 rgba(0, 0, 0, 0.02);
  ```
- `Card Anatomy`：标题与描述置于卡片**外侧下方**，呈现当代画廊展陈质感；
- `Text Hierarchy`：正文采用 Slate-900 / Zinc-900（如 `#0F172A` / `#18181B`），次级注释采用 `#64748B`，占位微弱信息采用 `#94A3B8`。

#### B. 深色轨（Dark Track · 精密微暗面板范式）
高品质深色界面的核心是**微光漫反射与单像素半透细线**：
- `Canvas (60%)`：深岩黑、钛矿黑（如 `#090B0E` / `#0D110F` / `#0F1115`）；
- `Surfaces (30%)`：微暗半透明面板（`rgba(255, 255, 255, 0.035)` 或 `#12171E`）；
- `Hairline Border`：单像素微透细边框（`1px solid rgba(255, 255, 255, 0.08)`），搭配卡片顶部微透内高光（Inner Refraction: `box-shadow: inset 0 1px 0 rgba(255,255,255,0.1)`）；
- `Ambient Glow`：背景微光使用半径受控的暗柔扩散光（`radial-gradient(circle at 50% 0%, rgba(Accent, 0.08), transparent 70%)`）。

### 4. 色彩一致性与单点聚焦约束
- **色温全局一致性**：单个项目中，所有中性色调必须严格统一，严禁混用冷灰与暖灰；
- **强调色单点化**：主强调色（Accent）只能出现在核心 Mark、单一 Primary 按钮与焦点环，严禁铺成大面积底色。

## 三、字体设计（性格与声音的关系）

### 1. 拒绝无脑默认 Inter
- **现代科技 / 极客工具 / 生产力**：`Geist` / `Satoshi` + `JetBrains Mono`（冷峻、精密、现代）；
- **人文叙事 / 生活方式 / 杂志编辑感**：`Outfit` / `Cabinet Grotesk` + `Newsreader` / 高质感 Serif；
- **严谨数据 / 企业金融 / 医疗健康**：`Plus Jakarta Sans` + `SF Pro Display` + 等宽数字；
- **场景铁律**：数据看板与控制台**严禁使用 Serif 衬线体**。

### 2. 行长、行高与数据对齐
- **正文行长**：正文段落容器强制使用 `max-w-[65ch]`（50 ~ 75 字符），防止横向视线扫描疲劳；
- **正文行高**：保持在 `1.5 ~ 1.65` 倍；
- **数据对齐**：金额、时间、度量指标强制开启表格等宽数字（`font-variant-numeric: tabular-nums` 或 Mono 字体）。

## 四、组件规范与 Anti-Card Overuse

### 1. 反卡片滥用（Anti-Card Overuse）
- **不要所有信息都装进 Card**：当页面信息密度高时，卡片套卡片会导致严重的视觉噪音与压迫感。
- **轻量解法**：使用无边框裸排、顶部 1px 单线（`border-t border-slate-200/50`）、列表分割线（`divide-y`）或单纯增加负空间来进行逻辑分块。

### 2. 交互状态物理与性能铁律
- **7 态完备性**：Default, Hover, Focus-visible, Active, Loading (骨架屏，拒绝转圈 Spinner), Disabled, Empty/Error；
- **弹簧阻尼微动效**：交互反馈采用 `type: "spring", stiffness: 100, damping: 20` 或 `cubic-bezier(0.16, 1, 0.3, 1)`；
- **GPU 性能**：动效严格限制在 `transform` 与 `opacity`；常驻循环动效隔离在独立 Client Component 中。

## 五、防止千篇一律与关系审计

完整新作先按 [UI 审美综合](ui_aesthetic_synthesis.md) 从 Content DNA 形成结构假设；代码提交前执行 Pre-emit 自省 6 轴评分，确保无 Anti-Slop 违规违纪。

定稿前执行**关系审计**：
1. **归因测试**：关键形式能否指回当前业务本质与任务要求；
2. **替换测试**：隐藏名称与主图后，页面骨架是否仍无损适用于竞品；
3. **三层同质化检查**：分别检查表层语言、结构语法和情绪基调；
4. **近期作品比较**：判断重复是品牌连续性，还是未经思考的懒惰模板。
