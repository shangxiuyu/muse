# 演示文稿与现场演说全能实战手册 (Presentation & Web Deck Toolkit)

用于商业提案、战略决策汇报、融资路演、技术大会 Keynote、新品发布会以及现场演示文稿开发。
**核心哲学：美是关系的艺术。** PPT 的本质不是用来阅读的静态文档，而是一场演说者与观众在特定时间内共同经历的「现场视听旅程」。

> **AI 专注指南（Single Source of Truth）**：本手册为 Muse 演示文稿任务的**自包含全能作战指南**。Muse 的 PPT 本质上是 **UI 视觉与前端工程** 与 **文案叙事与语言艺术** 在舞台时空下的高阶集成。作为**专业演示执行器**，核心原则是**不交付第一个安全答案**，确保代表页在**结构上不同**。**处理任何 PPT 与演示任务时，必须先在项目根目录交付或对齐自包含的 `PPT.md` 契约，提出 3 组差异化视觉方向的前 2 张样张供用户确认，锁定全局宏观大纲、逐页详细账本与底色呼吸策略后，再行动手生成单文件 HTML Web Deck。** 深度视觉推导与平庸淘汰协议参见 [视觉方向](presentation/visual_direction.md) 与 [相遇与淘汰](presentation/encounter_and_rejection.md)。

## 一、 境：业务场景与受众心智探针（业务决定形式）

坚决不预先锁死风格（拒绝“只有风格 A 或风格 B”的套壳思维）。形式必须由具体业务场景与受众心智自然推导出来：

| 业务场景 | 受众心智与痛点 (JTBD) | 视觉形式与排版重心 (Form) | 底色与调性取向 (Tone & Background) | 节奏与呼吸策略 (Rhythm) |
|---|---|---|---|---|
| **高管汇报 / 战略决策** | 时间极贵、排斥花哨动效、只看结论、商业归因与行动选项 | 紧凑网格、因果拓扑链路、核心 KPI 标尺、零装饰废话 | 冷轧钛黑 / 深石墨蓝 或 稳重纯净浅底，**全局底色统一** | **统一底色 + 疏密呼吸**（高密看板与单结论交替） |
| **日常工作汇报 / 评审复盘** | 讲究严谨、务实、前后连贯，常需会后导出 PDF 异步阅读 | 结构化列表、前后对比看板、证据数据条、清晰信息架构 | **全局统一浅色纸感 / 冷灰白底**，避免频闪眩光 | **统一底色 + 尺度呼吸**（大字结论 vs 细节实证，幕封温和过渡） |
| **技术大会 / 架构分享** | 讲究工程严谨、数据事实、看重系统拓扑与代码细节 | 高对比代码块、系统数据流动图、吞吐量柱状图、等宽字体 | 极简终端暗色、精密发丝线、冷钛银，**全局深色统一** | **深色统一 + 密度呼吸**（代码/拓扑密集页 vs 原理金句疏页） |
| **融资路演 (Pitch Deck)** | 寻找确定性与天花板、看重市场规模与商业模式闭环 | 强痛点刺痛、极简大留白、单点大字报、团队与商业证明 | 极简高留白底色 + 克莱因蓝 / 琥珀金 | **舞台模式（可选）**：破冰/高潮页可做温和反色提神 |
| **新品发布 / 品牌大会** | 追求情绪共鸣、生活方式向往与舞台沉浸感 | 电影级全景画幅、非对称大字号、大面积呼吸留白 | 客体专属提纯色、温润纸墨色板 | **舞台明暗交替（可选）**：深浅反差制造戏剧性起伏 |

## 二、 选：三向风格探索与 HTML 真实样张门禁（Visual Direction Gate）

**严禁“文字报菜名”偷懒（Anti-Textual Slop）**：AI **严禁**仅在对话中用文字口头描述风格（如只打字说“方案 A 是极简商务风，方案 B 是日系纸感风，请问您选哪个”）。文字描述与真实视觉严重脱节，本质仍是逼用户“开盲盒”。

AI 在正式生成完整 Deck 前，**必须通过 HTML 真实代码渲染出 3 套视觉画板**：

1. **构建 3 组差异化竞争假设**：
   * 基于业务情境推导 3 个具有明显结构、气质与调色板差异的视觉假设（例如：方案 A · 权威克制冷白 / 方案 B · Bento 模块科技纸感 / 方案 C · 高反差终端深色）；
2. **编写 HTML 渲染前 2 张真实样张（共 3 组 × 2 页 = 6 张真实幻灯片）**：
   * 必须在项目目录输出可视化的候选画板（如 `preview_candidates.html` 或 3 组样张 HTML）；
   * 每个方案包含真实的 **封面（Cover） + 核心图表/架构内页（Core Content）** 2 张关键页；
   * 用户打开浏览器即可**所见即所得**地亲眼观察字体渲染、字号级差、网格间距、色彩对比与真实留白；
3. **用户视觉确认后启动全量开发**：
   * 用户在直观看到 3 套真实视觉成品后做出选择（或提出微调建议）；
   * 确认选型后，正式记录至 `PPT.md`，AI 再基于选定方案的代码骨架全量展开完整 Deck。

## 三、 策：屏人二重奏（角色清晰分工）

演说的本质是台上的人与屏幕上的视觉形成的合奏。坚决消灭“把 PPT 当提词器、屏幕塞满文字让人读”的致命错误：

1. **屏幕的职责（视觉冲击与直观证据）**：
   * **一个情绪锚点**（一句穿透性的观点或反差金句）；
   * **一个硬核证据**（一张不可辩驳的数据图表、拓扑架构或真实照片）；
   * **2 秒原则**：观众看一眼屏幕在 2 秒内理解核心结论，然后注意力自然回到演讲者身上。
2. **演讲者的职责（逻辑推演与情绪心流）**：
   * 交代背景故事、阐述因果关系、引导转场、与观众眼神互动；
   * 屏幕绝不抢夺人的表达，人绝不朗读屏幕上的文字。

## 四、 骨：双层大纲体系与呼吸节律（Theme Rhythm）

PPT 是时间轴上的视听流动，必须建立清晰的双层大纲与叙事呼吸感。

### 1. 宏观五段式叙事弧
$$\text{Hook (破冰悬念/反常识数据)} \longrightarrow \text{Context (定调背景与战场)} \longrightarrow \text{Core (核心论据/架构)} \longrightarrow \text{Shift (戏剧性转折/核心解法)} \longrightarrow \text{Takeaway (金句收束/行动召集)}$$

### 2. 场景自适应的呼吸节律规则
* **严肃汇报 / 商务工作模式（默认推荐）**：
  * **底色一致性**：全篇保持统一的底色（全套稳重白底/冷灰底，或全套暗色终端底），严禁频繁翻转黑白产生会议室频闪与阅读割裂；
  * **密度呼吸**：通过**密页（High Density: 密集架构/对比看板）**与**疏页（High Breathing: 大字金句/单关键指标/大留白）**的交替形成呼吸；
  * **章节幕封**：跨越核心章节时，允许使用温和的幕封进行阶段性停顿。
* **舞台演说 / 发布会模式（高级可选）**：
  * 允许在 Hook、Shift 与 Takeaway 关键高潮页启用深浅明暗反色，制造舞台戏剧张力。
* **防同质化红线**：
  * 严禁连续 3 页出现同一种信息密度与排版骨架（严禁连续 3 页全是三等分卡片或全是大字报）；
  * 每 3~4 页必须出现一次**信息尺度或形式焦点的切换**（如从表格对比切换为单结论金句，或从拓扑图切换为步骤拆解）。

## 五、 契：标准交付契约与双层完整大纲（PPT.md）

全新制作或改版演示文稿前，**必须先在项目根目录交付并与用户确认自包含的 `PPT.md` 契约**：

```markdown
# PPT.md 演示文稿设计与演讲契约

## 一、 业务情境探针 (Context & Goal)
- 业务场景：[日常工作汇报 / 高管战略决策 / 融资路演 / 技术大会 / 新品发布 / 复盘分析]
- 受众心智：[决策者 / 团队同事 / 投资人 / 极客用户]（看重什么，排斥什么）
- 核心目标 (JTBD)：[达成什么共识 / 争取什么资源 / 推动什么决策]
- 节奏策略：[统一底色 + 疏密尺度呼吸（工作汇报推荐） / 舞台明暗交替（发布会可选）]
- 计划时长与页数：[如 15分钟，10~12页]

## 二、 视觉方向探索与选型确认 (Visual Style Gate)
- 方案 A（极简权威商务）：[极简大留白 + 冷钛黑/克莱因蓝，稳重高对比]
- 方案 B（现代科技纸感）：[微暖纸白 + Bento 网格 + 数据条，适合密集汇报]
- 方案 C（高反差终端深色）：[深石墨暗底 + 等宽字体 + 拓扑发丝线，适合技术分享]
- **用户确认选定方案**：[已确认方案 B，配前 2 张样张锁定]

## 三、 全局宏观篇章大纲 (Macro Deck Outline & Structure)
* **【第一幕 · 破冰与现状 (Hook & Context)】**（预估用时：3 分钟 / 第 1~3 页）
  - 核心逻辑：抛出核心命题 ➔ 揭示行业背景 ➔ 暴露当前关键业务卡点。
* **【第二幕 · 核心破局方案 (Core Solution & Architecture)】**（预估用时：7 分钟 / 第 4~7 页）
  - 核心逻辑：战略路径推导 ➔ 系统整体拓扑 ➔ 3 个核心执行模块细节拆解。
* **【第三幕 · 业务实证与成效 (Evidence & ROI)】**（预估用时：3 分钟 / 第 8~10 页）
  - 核心逻辑：前后对比看板 ➔ 关键指标量化改善 ➔ 风险防守机制。
* **【第四幕 · 行动计划与收束 (Roadmap & Call to Action)】**（预估用时：2 分钟 / 第 11~12 页）
  - 核心逻辑：里程碑排期 ➔ 所需资源支持 ➔ 愿景总结与进入 Q&A。

## 四、 逐页台前幕后详细大纲账本 (Slide-by-Slide Detailed Ledger)
| 页码 | 页面属性/密度 | 页面核心任务 (Purpose) | 屏幕呈现重点 (Screen: 一眼即明的数据/大纲要点) | 台上讲述要点 (Speaker Talk: 演讲者口径) | 转场与心理引导 (Transition) |
|---|---|---|---|---|---|
| **01** | Cover (疏页) | 抛出核心命题 | 极简主标题 + 一句穿透性副标 + 发言人信息 | 直奔主题，点明今天汇报的核心议题 | “在进入方案之前，我们先看一组真实数据...” |
| **02** | Problem (密页) | 暴露三大业务卡点 | 3 组痛点指标标尺 (如 73%) + 根因归因看板 | 剖析数据背后的业务堵点，建立紧迫感 | “针对这三大痛点，我们的整体破局思路是什么？” |
| **03** | Agenda (导引) | 建立全局认知框架 | 3 大破局模块索引与逻辑链条 | 交代后续推演结构，引导听众心流 | “首先看第一部分：架构重塑...” |
| **...** | ... | ... | ... | ... | ... |
| **12** | Action (收束页) | 明确推进计划与共识 | 阶段性里程碑 Roadmap + 关键资源支持清单 | 总结共识，明确下一步行动，表达信心 | “感谢各位，请大家提问与指导。” |
```

## 六、 术：前端工程系统与现场演说双屏交付

Muse PPT 默认交付**单文件 HTML Web Deck（`index.html`）**，完全继承 UI 模块的前端工程规范：

### 1. 排版与视觉工程规范（继承 UI 手册）
* **16:9 纵横比自适应**：居中视口锁定，大屏/投影完美铺满，杜绝滚动条。
* **负字距精密系统**：Display 大标题（`-0.03em ~ -0.05em`），行高 `1.05 ~ 1.15`，严禁大标题斜体；正文字距正常，行高 `1.6`。
* **色彩 6:3:1 面积黄金律**：
  * `Canvas (60%)`：深钛黑（`#0C0E12`）或 暖白纸色（`#F8F9FA`）；
  * `Surfaces (30%)`：半透面板（`rgba(255,255,255,0.04)`）或 纸质容器（`#FFFFFF`）；
  * `Accent (10%)`：单点高反差功能色（克莱因蓝、琥珀金、翡翠绿等）。
* **坚决剔除 AI 廉价味（Anti-AI Tropes）**：
  * 严禁纯黑死黑 `#000000`；
  * 严禁紫蓝霓虹大渐变；
  * 严禁无意义的悬浮发光卡片。
* **CleanShot 级证据图美化**：对于用户提供的截图、代码或图表，自动套用 16:10 / 21:9 画布容器，加单像素发丝线与微漫反射投影。

### 2. 现场交互与演说双屏系统 (Presenter Engine)
* **键盘与触控**：`←` `→` / `空格` 切页，`F` 键全屏；
* **`ESC` 全景索引**：按 ESC 呼出 16:9 全局宫格缩略图，自由跳页；
* **`P` 键分屏演讲者提词系统**：
  * 独立弹出演讲者窗口，包含：**演说秒表计时器、实时页码、以及从 `PPT.md` 注入的【本页目的】、【台上提词口径】与【转场过渡词】**；
  * 观众大屏与演讲者提词卡保持毫秒级双向同步。

## 七、 验收与五大平庸淘汰测试 (Anti-Slop Audit)

渲染完成后，隐藏设计说明，仅凭屏幕成品执行残酷测试：

1. **替换测试**：换掉标题和 Logo，如果绝大多数页面还能原样套给别人用，**判定淘汰（缺乏具体性）**。
2. **提词器测试**：如果页面上文字超过 3 行，逼迫观众去读字而不是看演讲者，**判定淘汰（屏人错位）**。
3. **安全答案测试**：充斥着毫无业务逻辑的三等分卡片、胶囊标签与装饰线条，**判定淘汰（模板偷懒）**。
4. **跨页节奏测试**：缩略图一拉开，全是同一页面语法的机械复制，毫无信息尺度、密度与呼吸反差，**判定淘汰（缺乏呼吸感）**。
5. **解释依赖测试**：拿掉小作文辩护，画面本身无法独立传递张力与结论，**判定淘汰（形式未兑现）**。
