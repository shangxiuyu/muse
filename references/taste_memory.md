# Taste Memory｜用户品味记忆

Taste Memory 不是一份固定“风格画像”，而是人的经验与共鸣进入 Muse 的方式。它保存可追溯、会随情境修正的个人审美资产，让 AI 知道用户在什么时刻对什么产生了怎样的反应、哪些原因是用户说出的、哪些只是 AI 推断，以及这种判断有多确定。

它不是公共审美方法的附属配置。基础审美推理提供共享的观察语言，Taste Memory 提供通用规则无法拥有的生命经验、文化记忆与个人选择；两者共同形成新的审美假设。

## 五类个人审美资产

| 资产 | 用户语言 | 能说明什么 | 不能自动说明什么 |
|---|---|---|---|
| `reference` 参考 | “收藏这个”“分析这张图／这篇文章” | 看过、分析过或收藏过什么 | 用户喜欢它，或喜欢其中全部特征 |
| `reaction` 审美反应 | “喜欢它的排版，不喜欢配色”“说不清，但这里让我停住了” | 用户在具体情境中对明确对象的第一手反应 | 反应原因已经知道，或以后都应采用 |
| `system` 审美系统 | “总结这批参考和反应中的共同关系” | 一组有证据的可迁移原则、适用边界与未知项 | 系统已经成为用户的长期选择 |
| `preference` 品味选择 | “以后研究报告都保留这种证据密度” | 带场景的 candidate 或用户明确 confirmed 选择 | 永久人格，或适用于所有媒介和情境 |
| `application` 应用经验 | “把它用到这次发布会，第二版更好” | 某套原则在一次真实任务中的实现与反馈 | 一次成功已经证明普遍有效 |

五类资产不能自动晋升。`reaction` 是“用户确实这样反应过”的事实记录，不是 candidate preference；只有从反应提炼出的可迁移判断才可能成为候选，只有用户明确长期意图才成为 confirmed preference。收藏可能只是“以后再看”；喜欢整体不代表喜欢每个局部；审美系统 ready 只表示证据足以参考；应用成功一次也不等于长期通用偏好。真实反应可以没有清楚原因，不能为了结构完整让 AI 补造解释。

## 审美反应是第一手资料

用户的反应不只是“赞成／反对”一个设计参数。一次值得保存的审美反应可能包含：

- **对象**：整体、局部、某段文字、一个转场，或尚无法定位的瞬间。
- **情境**：在什么任务、媒介、设备、环境和心境中发生。
- **发生时间**：反应实际发生的时间；无法确定时明确为 unknown，不拿入库或修订时间代替。
- **原话与强度**：用户实际怎么说，是轻微偏好、明确排斥，还是被触动。
- **感受**：平静、信任、压迫、惊喜、亲近、疏离，或“说不清”。
- **解释状态**：用户明确说明、AI 推断、双方共同形成，或 unknown。
- **矛盾与例外**：与既有品味是否冲突，冲突是否来自不同情境。

保存原始反应，再另行提炼可迁移原则。system 的原则可直接引用具体 reaction 版本，形成“真实反应 → 推断”的证据链。`reaction.status=active` 只表示记录未归档，不表示用户确认了长期偏好。不要为了得到整洁画像而抹去含混、矛盾和变化；它们可能正是理解个人品味最重要的证据。

## 学习循环

### 收藏 Collect

保存来源、时间和覆盖范围；用户同时表达感受且授权长期保存时，将原话、反应对象、实际发生时间、情境和解释状态写成独立 `reaction`。尽量记录“喜欢哪里”而不是只留 URL；发生时间或原因不清楚时分别保持为 unknown，不补造。原件是否复制到私人目录取决于授权、版权和可访问性。

### 拆解 Deconstruct

把材料拆成可观察关系，而非风格标签：焦点、层级、比例、密度、留白、色彩职责、字体角色、图像关系、句法节奏、叙述姿态、运动与声音。明确区分：

- **观察**：材料中实际存在什么。
- **解释**：这些关系可能产生什么作用。
- **审美反应**：用户真实表达的喜欢、排斥、触动、迟疑或无感。
- **品味信号**：从反应中形成的可迁移解释；AI 提出的必须标为待确认假设。
- **未知**：当前材料无法证明什么。

### 推断 Infer

多个样本可以形成聚类或审美系统，但必须保留反例和范围。用“在研究报告中偏好紧凑、清晰的证据层级”代替“用户喜欢极简风”。若两个样本只共享表面颜色，不足以推断共同系统。AI 应提出“这可能意味着什么”，不能把自己的因果解释写成用户内心事实。

### 确认 Confirm

只有用户明确表达长期意图时写为 confirmed。确认的是带场景的原则，不是永久人格。例如“以后产品复盘都保留密集数据表”不应扩张成“所有作品都要高密度”。用户确认“不知道原因，但以后想保留这种感觉”同样有效；保存目标感受和参考，不伪造具体机制。

### 调用 Retrieve & Apply

先按媒介、任务、受众、气质和限制查找，再读取少量最相关资产的完整证据。应用时：

1. 说明为什么此资产适合当前任务。
2. 保留其核心关系，不照搬颜色、字体、构图或句子。
3. 当前明确要求、事实、可用性和品牌约束始终优先。
4. 找不到合适资产时回到 Aesthetic Reasoning，不硬套个人库。

### 复盘 Learn

记录使用了哪个版本、做了哪些适配、真实结果和反馈来源。反馈先修当前作品，再判断应更新 application、缩小／扩大 system 的边界，还是写入用户明确确认的 preference。

## 偏好卡的最小语义

任何品味信号至少应尽量回答；用户未提供的部分保持 unknown：

- **对象**：喜欢／不喜欢的是整体还是具体局部？
- **原则**：可迁移的关系是什么？
- **原话与感受**：用户实际表达了什么，包括“说不清”。
- **原因**：用户明确说了什么；若是 AI 推断，必须标明，不能覆盖原话。
- **范围**：适用于什么媒介、任务、受众或情境？
- **证据**：来自哪个样本、反馈或应用？
- **状态**：candidate 还是 confirmed？
- **例外**：何时不应采用？

“简约、现代、高级、有质感”只能作为检索标签，不能单独成为偏好原则。

## 隐私、授权与所有权

个人库位于 skill 之外，依次使用用户指定位置、`MUSE_VAULT_DIR`、默认 `~/Documents/Muse`。只读检索不创建库；只有明确收藏、学习或长期记忆授权时写入。用户要求删除时，区分归档和彻底删除，不把仍保留历史与备份的归档称为删除。

具体存储、版本、证据链接和命令见 [资产库协议](asset_library.md)、[写入格式](asset_schema.md) 与 [个人品味记录协议](memory_protocol.md)。
