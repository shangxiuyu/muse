# 审美复盘：观察、解释、修改、复看

完整成品先按 [验收协议](acceptance_protocol.md) 检查阻断项。本文件用于解释问题和形成修改，不能把创作者自评当成独立验收。

局部任务只检查影响范围，不要求每次输出整份报告。

纯文本的公开发布、整篇改写、去 AI 味和声音评审同时使用 [文本质量复核](toolkit/text_quality_protocol.md)；不以视觉维度替代段落推进、作者声音和保真检查。

## 明确观察对象

记录目的、受众、载体与不能丢失的内容。区分观察事实、作用解释、审美假设和人的真实反应，并分别判断审美力量、设计适切、伦理完整与个人共鸣。仅见源码不能声称看过渲染，仅见截图不能声称键盘操作正常，没有用户反馈不能声称作品已产生预期共鸣。

| 维度 | 观察问题 | 验证方式 |
|---|---|---|
| 意义与任务 | 首先看见的是主张或主要任务吗？ | 对照 brief，定位行动与证据 |
| 层级与路径 | 从哪里开始，接着看哪里？ | 缩览、实际尺寸阅读、任务走查 |
| 关系与节奏 | 分组、比较、疏密表达了内容关系吗？ | 组内／组间距离、重复与例外、段落／镜头顺序 |
| 情境与性格 | 适合受众、品牌且有辨识度吗？ | 对照已确认参考，解释选择 |
| 可读与完整 | 文本、状态、数据和边界可用吗？ | 真内容、长值、窄屏、焦点、静态替代、导出 |
| 细节一致 | 同角色的字体、颜色、裁切和节奏一致吗？ | 同时看变量与实际结果 |
| 事实与披露 | 具体名称、数字、来源和判断有何依据？ | 对照作品契约的内容账本，实际打开来源 |
| 响应式语义 | 窄屏是否仍保留任务、限定、来源和披露？ | 对比断点内容与关键路径，不只查溢出 |
| 时间与反馈 | 运动是否被感知并解释变化？ | 实际播放或操作，观察开始、中间和结束 |

事实、任务、响应式语义和无障碍缺陷不能由风格分抵消。阻断项清零前不报告通过；未检查写未验证。

## 修改有证据

使用 **位置／现象 → 影响 → 可能原因 → 最小修改 → 复看结果**。

弱反馈：“不够高级，换成某个流行工具的风格。”

有效反馈：“价格与附加说明同样大小，扫读时难分决策信息。加强价格层级，将说明放在下方，保留现有暖色品牌。修改后检查移动端价格与套餐的对应关系。”

优先处理最大的 1–3 项：内容错误和行为阻塞，层级与结构，最后细节。记录收益与代价，避免一次改太多变量。

## 比较前后

保持内容、载体和观察条件一致。记录修改、改善、代价与新退化。换字或换色不自动等于提升，原版更合适就保留。

偏好与可用性冲突时先寻兼顾方式，如保留柔和气氛但提高有效文字对比；需要权衡时呈现具体差异。

## 反馈分类

- “金额算错”是事实纠错，不生成品味。
- “这页留白太多”先按当前场景修改。
- “以后我的研究报告都紧凑”是明确场景偏好，可记 confirmed。
- “喜欢这个”只证明认可案例，不能自行推断全部参数获认可。

候选原则带适用情境、来源和例外，见 [偏好协议](memory_protocol.md)。
