## 📖 核心哲学：美是关系的艺术

大多数 AI 生成内容之所以带着强烈的**「AI 塑料感」**（满屏饱和紫蓝渐变、无脑大圆角卡片堆叠、机械居中对齐、公文式排比套话、无重力漂浮光斑），根本原因在于模型在**孤立地拼凑视觉或词汇符号**。

**Muse 的第一性原理：美不是静态规则，而是关系的艺术。**

- **孤立元素无所谓美丑**：色彩、间距、字体、动效单独存在时没有优劣；只有当它们与具体情境、受众心智和深层内容达成恰当共振时，美才会发生。
- **判断先于生成**：在敲下第一行代码、落笔第一段文字前，先完成情境解构，确立交付契约。
- **跨端同构，自适应推断**：美学母体是**表层系统**的唯一真实源，由设计系统深层语言自适应推导全端形态，不把移动端降级成「缩小版网页」。
- **最终目标是「恰当」，而非「自恋式惊艳」**：最好的设计与文案让用户聚焦于任务与内容本身，剔除一切喧宾夺主的无效装饰。

## ⚙️ MUSE 双引擎运转拓扑

Muse 不试图垄断审美，而是通过**公共推理**与**私有品味**的解耦协作，持续推导并校准最优方案：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                              MUSE 双引擎运转拓扑                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  [输入: 业务目标 / 真实内容 / 用户参考]                                        │
│         │                                                                    │
│         ▼                                                                    │
│  ┌─────────────────────────────┐         ┌────────────────────────────────┐  │
│  │ Engine 1: Aesthetic Reason  │ ◄───────┤ Engine 2: Taste Memory Vault   │  │
│  │ · 基础审美推理 (公共 / 只读) │         │ · 真实反应解构 (Reaction)      │  │
│  │ · 情境与内容 DNA 探针        │         │ · 私有偏好 (personal_dna)      │  │
│  │ · 10 大美学母体自适应推断   │         │ · 专属作者声音 (Author Voice)  │  │

│  └──────────────┬──────────────┘         └────────────────────────────────┘  │
```

1. **Aesthetic Reasoning（基础审美推理引擎）**：随 Skill 开箱即用，负责观察、比较和解释形式关系，从内容与任务情境推导审美假设，落实到排版、层级、对比、材质与节律。
2. **Taste Memory（用户品味记忆引擎）**：存放于 Skill 目录之外的私有资产库，记录用户的真实审美反应、已授权的偏好与作者声音画像，随交互深度持续自进化。

## ⚡ 五大媒介交付契约体系 (Contract First)

**先立契约，再落作品。** 针对不同媒介特性，交付严格分流：

### 1. 💻 UI / UX 界面与前端产品
- **标准契约**：先输出 [DESIGN.md](DESIGN.md)，锁定任务、审美假设、设计系统 Tokens、结构、核心对象、运动节律与验收条件。
- **工程解耦**：强制模块化实现 —— `index.html`（语义骨架）+ `index.css`（设计系统）+ `app.js`（交互状态）。拒绝单文件混排。
- **指引索引**：[UI 适配器](references/toolkit/ui_adapter.md) · [美学文法](references/toolkit/ui_grammar.md) · [视线心流](references/toolkit/ui_interaction_flow.md) · [创新算子](references/toolkit/ui_innovation.md) · [组件范式](references/toolkit/ui_creative_arsenal.md) · [负向底线](references/toolkit/ui_floors.md)

### 2. ✍️ 文本叙事：立足核心判断
- **标准契约**：先输出 [WRITING.md](WRITING.md)，锁定受众心智、叙事动线、文风基调与**核心判断**。核心判断必须是「一句能被反驳的真知灼见」，杜绝正确而空洞的废话。
- **内容验收**：执行〈可反驳测试〉防假大空；执行〈删题测试〉检验结构咬合度；通过 24 种反 AI 腔微创手术去油。
- **指引索引**：[文本实战手册](references/toolkit/text_narrative_tool.md) · [文本质量复核](references/toolkit/text_quality_protocol.md) · [作者声音画像](references/personal_assets/author_voice_profile.md)

### 3. 📝 规约型文本：提示词 / SOP / 检查表
- **标准契约**：先输出 [PROMPT.md](PROMPT.md)，逐条建立「规则 / 判定动作 / 反例场景」。
- **行为检验**：规约是给模型或系统执行的代码，不是抒情散文。每条规则必须能构造出「AI 这样做就违规」的具体反例。文件写入 `<!-- muse:genre spec -->` 即可激活专用规约检查口径。

### 4. 📊 演示文稿与现场演说
- **标准契约**：先输出 `PPT.md`，执行「屏人二重奏」（投影幕只留焦点证据与情绪，台词在演讲者口中）。
- **呼吸节律**：Theme Rhythm 视听明暗交替，生成单文件即开即演、原生支持全屏快捷键的 Web Deck。
- **指引索引**：[演示实战手册](references/toolkit/presentation_tool.md) · [演示视觉方向](references/toolkit/presentation/visual_direction.md) · [演示表层流派](references/toolkit/presentation/archetypes.md) · [相遇与淘汰](references/toolkit/presentation/encounter_and_rejection.md)

### 5. 🎨 概念视觉生图与艺术指导
- **标准契约**：先输出 [IMAGE.md](IMAGE.md)，建立画幅意象账本、留白安全区与微质感规范。
- **物理真实**：杜绝无理由的漂浮与油腻塑料光，坚持物理重力、单一主光源（色温自洽）与纤维微质感。
- **指引索引**：[图像实战手册](references/toolkit/image_visual_tool.md) · [摄影布光手册](references/toolkit/photography_tool.md) · [视觉语法](references/visual_grammar.md)

## 🚫 负向底线与显式声明 (Anti-Slop)

底线机制用于自动阻断**无意识的 AI 套路倾向**，而非限制艺术表达：

```
                    典型 AI 塑料味                        MUSE 的替代做法
   ┌──────────────────────────────────────────┬──────────────────────────────────────────┐
   │ 🟣 大面积高饱和紫蓝荧光大渐变             │ 🎨 从真实客体推导 4–6 色具名温润调色板      │
   │ 📦 滥用卡片嵌套卡片（Card in Card）       │ 📐 负空间呼吸、1px 物理细线、无框非对称排版 │
   │ 🔲 机械居中对齐、字间距松散平庸          │ 🔠 负字距收紧、左对齐力场、明确视觉入口     │
   │ 🤖 机械排比、充满爹味与说教公文          │ ✍️ 具象名词驱动、动宾直击痛点、短句给决断   │
   │ 📄 演示把大段讲稿文字搬上投影幕          │ 🎯 屏人二重奏：单页单焦点、巨幅关键指标     │
   │ 🪄 画面无光源逻辑的浮夸光斑与胶皮质感    │ 💡 单一真实主光源、微观材质漫反射真实质感   │
   └──────────────────────────────────────────┴──────────────────────────────────────────┘
```

**例外声明机制**：当某些特定母体确实需要使用纯黑、单色 Emoji 或特定间距时，允许在文件顶部添加显式可见的声明：
```html
<!-- muse:allow pure-black: 瑞士黑白排印以纯黑为骨架色，属于本母体的形式语言 -->
```
偏离被允许，但不被隐藏。事实真实性、内容来源与无障碍（可访问性）底线**不可声明豁免**。

## 🛠️ 纯净零依赖工具链

要求 Node.js 22+，**检查脚本全原生实现，无任何第三方依赖**，无需 `npm install`：

```bash
node scripts/audit.js                    # 技能自审（链接可达/契约/版本/规则自合规/公共证据）
node scripts/lint_ui.js <文件或目录>      # 对前端界面文件执行负向底线与例外检查
node scripts/lint_text.js <文件或目录>    # 对文本内容对照 24 种反 AI 腔病灶执行定位
node scripts/lint_text.js --selftest     # 双向验证规则集（抓得住反例，不误伤正例）
node scripts/asset_library.js location   # 查询当前品味库（Taste Vault）位置与状态
```

```bash
npm test                                 # 等价于 node scripts/audit.js
```
