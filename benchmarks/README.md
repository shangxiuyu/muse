# 验证分层

## 工具与资产

npm test 会执行实际 fixtures、知识目录与链接检查，以及存储／迁移／CLI 边界测试。缺失基准、空案例、未知类型、非法记录、失败测试均阻断。对比度函数由独立工具测试验证；Muse 不内置色板。没有生成作品时不能宣称审美通过。

golden_cases.json 中每个案例有具体输入与可观察的提示规则。它测试工具是否按已声明边界工作，不检验画面是否好看。静态脚本不检查完整 DOM、CSS 级联或真实操作。

## Agent 行为

behavioral_cases.json 提供跨情境请求和人工判据。评估者只拿任务、技能与原始素材执行，观察者随后按判据复核，不要求命中特定措辞。

每个案例同时声明 `required_observation` 和 `blockers`。前者规定必须真实观察的证据，后者优先于评分：出现未标记虚构、任务中断、语义在断点丢失、动效只在代码中存在或虚假验证声明时，案例直接失败。检查项通过数量不能抵消阻断项。

比较版本时固定模型、输入和资源预算，保存实际作品、操作记录、使用的技能快照及验证范围。按任务服从、事实保真、内容关系、情境适配、表达辨识、可读性分别评价，不能用总平均掩盖事实或功能退化。

视觉任务需观察渲染；交互需操作，动效需实际运行。来源声明需打开原始材料逐项核对；响应式需检查必要内容和披露是否保留，不能只查溢出。未观察写未验证。创作者自评和独立观察分开保存。单轮小样本只用于发现问题，不据此声称稳定提升百分比。教学案例不是独立 hold-out；后续用未收入案例库的新任务检查迁移能力。

运行 `npm test` 只验证这些案例定义完整，并明确输出行为评测未执行。完整前向评测按照 [前向测试协议](forward_test_protocol.md) 执行，并依照 [成品验收](../references/acceptance_protocol.md) 保存 brief、作品契约、成品、截图或播放记录、关键路径结果、自评和独立复核。

## 偏好学习

测试模板无作者偏好；候选不会自动升级；同源记录幂等；引号／反斜杠／换行保真；错误输入不改文件；迁移保留原始文件与来源。审美意义仍需 Agent 根据上下文判断，脚本不模拟学习率。

## 参考提取与资产复用

自动化测试覆盖同批存储、证据引用、原件版本、重复写入、版本冲突、归档、应用关联、失败回滚及空库读取。格式有效不证明观察真实或推断合理。

行为试用应让 Agent 实际读取原材料、保存系统、按任务检索、产出作品并处理范围不同的反馈。文章试用不能替代网站或图片实样；静态图试用也不能证明交互提取准确。保留真实失败与未验证范围，不将教学试用所得偏好加入用户库。

3.4 新增五类文字前向任务：仅诊断而不猜作者身份、保留个人声音、证据约束的品牌文案、同一事实的体裁差异，以及对成立原文保持克制。自动测试只验证这些任务和判据可读取；真实效果仍需固定输入执行、保存前后文本，并由独立观察者复核保真、声音、体裁适配和新退化。

3.4.1 新增个人声音资产边界任务，分别观察一次性样本、明确保存声音画像和明确确认长期偏好。评测必须检查实际个人库与公共知识前后状态；不能只根据回复中的“已保存”判断通过。

4.0.0 新增两类架构级前向任务：空个人库下的跨媒介审美创作，以及对整体收藏、局部喜欢和明确否定的分层学习。前者检查 AI 是否真正从内容形成意图并跨媒介迁移关系；后者检查品味记忆是否保留对象、范围、状态与未知，而不是把收藏和推断自动升级为偏好。

4.1.0 将空库任务改为审美推理任务，并新增“有审美力量但存在伦理问题”的评审场景。评测检查 Agent 是否分开审美力量、设计适切、伦理完整与个人共鸣，是否把人的真实反应与 AI 推断分开，以及是否避免宣称自己已经证明作品是美的。

4.2.0 新增三类 UI 审美综合前向任务：同一内容在不同使用情境中的结构分化、相同技术约束下不同内容产生不同自身形式，以及高频工具保留成熟模式时的克制。4.4.0 将强制 Signature Move 改为可为 none 的 Distinctive Relation，评测检查 Content DNA 是否来自可核对内容，审美假设是否能预测多项形式选择，辨识关系与克制规则是否有内容依据，以及归因、替换、三层同质化和近期作品比较是否基于真实成品。自动测试只验证任务与方法结构存在，不宣称设计质量已经提升。

4.3.0 新增两类 Taste Memory 前向任务：原因 unknown 的强反应保存，以及同一用户在不同情境中的矛盾反应。评测检查 Agent 是否把 reaction 当作第一手经验而非偏好结论，是否保留原话、对象、处境、解释来源和矛盾，是否只有在明确长期授权后才另写 confirmed preference。确定性测试覆盖链接、检索、公共隔离与写入失败回滚；仍不能代替真实用户对提取结果的确认。

4.4.0 要求 reaction 记录实际发生时间或 unknown，矛盾指向具体 reaction 版本，system 原则可以直接引用 reaction 证据。真实行为评测按 [前向测试协议](forward_test_protocol.md) 在隔离库执行；没有实际运行与观察记录时，仍必须报告 NOT RUN。

4.7.0 新增五类 UI 项目生命周期任务：已有目标的局部 direct edit、选定方向上的 replace、用户明确要求的 branch 比较、源码局部变化后的 Context Manifest 增量刷新，以及真实品牌 Logo 在多组件和窄屏中的保留。评测检查 Agent 是否选择最小且正确的迭代方式、维护可恢复版本、只读取必要变化、保留品牌资产来源，并继续以真实渲染和操作证据收口；自动测试只验证协议与任务定义完整。

4.9.0 将演示能力收束为审美导演：从内容中找到不可替代的力，提出结构上不同的竞争方向，选择有明确代价的表达，并用替换、安全答案、生命张力、跨页节奏和解释依赖测试淘汰平庸。新增真实失败案例，确保 Agent 不以可编辑、无溢出或自动测试为审美辩护；文件制作与格式验证由专业演示执行器负责。
